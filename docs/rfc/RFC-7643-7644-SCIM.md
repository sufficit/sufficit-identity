## Authentication and authorization

An in-house policy (`src/scim/ScimServiceCollectionExtensions.cs:52-56`): OpenIddict
bearer, authenticated user and required SCIM scope. `ScimClientPolicyMode`
has an `Observe` mode for migration, reported by `ProductionPostureCheck`
(`src/scim/ScimProductionPostureContributor.cs:26-31`), so that going live in
production in that mode requires acknowledgment.

Every denial is audited by `ScimAuthorizationAuditFilter`, which exists because a
refusal from the `[Authorize]` policy would leave no trace in the management
audit table (`src/scim/ScimAuthorizationAuditFilter.cs:18`).

## Filters

`ApplyUserFilter` (`src/scim/ScimProvisioningService.Support.cs`) translates the SCIM
filter into a typed LINQ expression over the `DbSet`. There is no SQL concatenation
anywhere in the repository — `FromSqlRaw` and `ExecuteSqlRaw` don't appear outside
of tests —, so the filter-injection class of vulnerability doesn't exist here.

Pagination is bounded: `startIndex` and `count` with a ceiling
(`ScimControllers.cs:82-90`), which prevents a full scan via a single call.
