# acr_values now asks for something

Plan: `PLAN-IDENTITY.md` section A4, last item. Completes the step-up work of
[`202609201100`](202609201100-authorize-step-up.md).

`acr_values` was parsed by OpenIddict and then ignored: a relying party asking
for an assurance level was silently given whatever the session already had, and
the conformance run noted the `acr` never echoed it.

The authorization endpoint now reads it. The strongest level the request asks
for is compared with the session's, and a session below it runs the ceremony
before the request produces anything — the same place, and the same receipt,
as `max_age`, `prompt=login` and a remembered second factor.

## What a voluntary request means here

OIDC Core 3.1.2.1 makes `acr_values` a preference, not a demand, and this
implementation treats it as one:

- a value this deployment does not recognise is **ignored**, not refused, so a
  client may send its own vocabulary alongside ours;
- a level the ceremony cannot reach is **attempted once** and then allowed
  through, with the token telling the truth about what happened. Password plus
  TOTP cannot become phishing-resistant by asking again, and the receipt is
  what turns "cannot" into one attempt instead of a loop. That case has its own
  end-to-end test, because it is the one that would hang a user forever.

`IAuthenticationContextClassMapper` gained the inverse of `Map`. It is
deliberately partial — it returns null for a vocabulary this server does not
speak — and `Parse` is a real interface member rather than a default one, so an
implementation cannot forget it and silently accept everything.

Discovery advertises `acr_values_supported` now that the endpoint acts on it.
The list stops at `loa3`: a phishing-resistant session satisfies that level but
is not separately requestable, so advertising it would promise something the
ceremony cannot deliberately produce. A test asserts every advertised value
parses back to the level it was mapped from, so discovery cannot promise a
value the policy would ignore.

## Verification

1,512 tests pass, Release warning-clean. Eleven new cases: the level matrix
(equal, above, below, strongest-of-several, unrecognised, empty), a session
with no level at all treated as the floor, the discovery round trip, and the
unreachable-level flow end to end. Disabling the rule fails five of them.
